# v0.7.0

Release type: minor capability release.

Release focus: diagnosis breadth (6 new symptom types, batch aggregation) and operator maturity (OLM, Prometheus, health probes).

---

## New Symptom Types

Six new Kubernetes failure symptoms are now diagnosed with rule-based fallback:

| Symptom | Severity | Description |
|---------|----------|-------------|
| `PVCPending` | warning | PVC referenced by pod is not in Bound state |
| `VolumeResizeFailure` | warning | PVC failed to expand its underlying volume |
| `NetworkPolicyBlocking` | warning | NetworkPolicy blocking required connectivity |
| `HPAMaxReplicas` | warning | HPA at maxReplicas ceiling, cannot scale up |
| `ResourceQuotaExceeded` | warning | Namespace ResourceQuota exceeded, blocking creation |
| `PDBDisruptionBlocked` | warning | PDB MinAvailable not satisfied, blocking disruptions |

### Fixes within new symptoms

- **PVCPending**: Fixed `getattr`-on-string bug when constructing the `message` field from PVC phase.
- **ResourceQuotaExceeded**: Fixed invalid `field_selector` (`reason=FiredCreate` is not a standard K8s Event field); now uses in-code message filtering.

---

## Batch Diagnosis Aggregation

When multiple events for the same workload arrive within a short window, the agent now aggregates them into a single diagnosis with batch impact summary.

- `K8S_DIAGNOSIS_BATCH_THRESHOLD` (default: 5) — number of events in window before triggering aggregated diagnosis
- `impactSummary` now includes `aggregatedWorkloads: string[]` listing affected pods/replicas
- Batch reports still write individual DiagnosisReports (one per workload), but the diagnosis reasoning covers the full blast radius

## Operator Maturity

### Prometheus Metrics (breaking rename)

All metrics are now prefixed with `k8s_diagnosis_` for Prometheus naming conventions:

| Old name | New name |
|----------|----------|
| `diagnosis_requests_total` | `k8s_diagnosis_requests_total` |
| `tool_calls_total` | `k8s_diagnosis_tool_calls_total` |
| `diagnosis_duration_seconds_count` | `k8s_diagnosis_duration_seconds_count` |
| `diagnosis_fallback_total` | `k8s_diagnosis_fallback_total` |

New metrics:

- `k8s_diagnosis_quality_score` (gauge) — overall quality score per diagnosis
- `k8s_diagnosis_batch_size` (histogram) — number of events aggregated per batch
- `k8s_diagnosis_uncertainty_total` (counter) — diagnoses with uncertainty flags

### Grafana Dashboard

8 panels covering: diagnosis rate, quality score, fallback rate, uncertainty rate, batch size, batch reports.

### Health Probes

Three HTTP health endpoints for K8s probe compatibility:

- `GET /healthz/ready` — K8s API + CRD connectivity check
- `GET /healthz/live` — process-level liveness
- `GET /healthz/startup` — model client readiness

### OLM Bundle

Operator Lifecycle Manager bundle added with:
- ClusterServiceVersion (CSV)
- Package manifest
- CRD definitions
- `bundle.Dockerfile`
- `OwnNamespace` and `MultiNamespace` install modes

## evidenceTimeline Reconstruction Fix

**Bug fix** (post-v0.7.0 merge, included in this tag):

Previously `evidenceTimeline` was taken directly from the model's JSON output, which was unreliable — the model often omitted events or hallucinated timestamps.

Now `_reconstruct_evidence_timeline()` extracts events from actual `get_pod_events`, `get_workload_events`, and related tool outputs stored in `tool_history`, deduplicates by `(signal, kind, name, timestamp)`, sorts ascending, and caps at 20 entries.

Also clears `tool_history` at `diagnose()` start to prevent stale data from prior calls from leaking into subsequent diagnoses.
